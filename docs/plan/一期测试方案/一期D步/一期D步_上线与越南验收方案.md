# 一期D步：人工客服、上线及越南访问验收

前提：前序功能按实际需要完成，本步另行批准上线操作。

## 1. 人工客服

选择支持中英文且越南可访问的人工客服渠道，只显示一个入口。第三方平台/费用、账号、坐席及隐私要求先确认，再按需加载插件。

验证在线/离线、手机、脚本失败及询盘兜底，不虚构在线状态。若只选择外部联系链接，明确标识而不是宣称站内聊天。

不部署 AI，不显示 AI 入口或推广文字；扩展方向保留在根目录参考文档。

## 2. 上线准备

- 企业信息、技术参数、证书、品牌授权及中英文内容审核。
- HTTPS、域名/备案（适用时）、邮件、隐私政策、公开与私有资源检查。
- SQL、文件备份和恢复演练，升级回退不丢失已提交询盘。
- 测试环境与生产隔离；正式域名批准后移除测试 noindex，输出正确 canonical/hreflang/sitemap。
- 确认Knife4j及原始OpenAPI路径限制，MySQL及Java内部端口不暴露公网；一期不启动Redis。
- 页面、接口、文件上传和媒体播放压测，监控 OOM、错误率及账单。

## 3. 越南访问方案继续有效

当前复用现有服务器，媒体由服务器独立磁盘目录提供，不接OSS。记录地域及节点，不默认新加坡或国内资源满足越南。

在河内/胡志明市，Viettel/VNPT/FPT 的固定及移动网络分时测试，覆盖晚高峰。

测试 DNS/TLS、首页及产品首屏、接口、语言切换、PDF、视频首帧、询盘和人工客服，分别记录服务器、媒体及第三方依赖的问题。

未实测不得声明已保证越南访问。若失败，先诊断应用性能、线路、DNS、本地媒体吞吐和客服平台，再按[二期总方案](../../二期方案/二期总方案.md)评估新加坡、OSS或CDN；更换厂商、迁移和购买须重新批准。

详细方向参考：[外贸与AI客服补充方案](../../外贸与AI客服补充方案.md)，其中OSS及AI仅为后续参考，不是一期依赖。

## 4. 验收

- [ ] 关键企业内容真实且已审核
- [ ] 官网/后台/询盘/媒体及人工客服闭环通过
- [ ] HTTPS、权限、备份恢复和回退验证完成
- [ ] 性能及资源容量有实际报告，2GB 不满足时已处理
- [ ] 越南测试有运营商、地点、时间和结果记录
- [ ] 未达标问题明确，不把国内访问结果替代越南验收
- [ ] 无 AI/知识库/转码点播依赖及调用
- [ ] 月预算、流量告警和运维责任人明确
