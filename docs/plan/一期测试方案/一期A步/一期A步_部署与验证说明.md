## 2. 已有服务器部署准备

先确认地域、系统/架构、Docker、磁盘和内存、原有业务、3100端口、测试域名及备案条件。未经授权不改现有站点。

使用 Node 24 LTS 在本地构建，部署 `.output`、`Dockerfile`、`compose.yml`；Windows 构建产物如有平台原生依赖，应使用同目标 Linux 架构环境重新构建，不能假定跨平台可运行。本项目输出以服务端 JS 为主，仍须在目标容器内验证。

本地安装并构建：

```powershell
npm ci
npm run build
```

Dockerfile 只复制构建结果，不在服务器执行 npm/Maven 构建。

经批准后在上传好的部署目录创建 `.env`，默认 `SITE_DEFAULT_LOCALE=zh`，联系方式为空不填虚假信息。

在服务器部署目录构建运行镜像并启动（需要可用 Docker 和基础镜像获取网络）：

```bash
docker compose up -d --build
```

本地 Docker 也可按目标架构预先构建并导出镜像后上传；服务器无法下载镜像时不盲目重试或切换未知镜像源。

默认只绑定 `127.0.0.1:3100`，通过已有 Nginx 独立测试虚拟主机反代。不要额外公开3100，不覆盖现有 Nginx 配置。

`website/deploy/nginx.conf.example` 是 HTTP 测试模板，公网上线前配置 HTTPS、域名和证书，并确认备案（适用时）。Cookie 无登录信息，HTTPS 仍是推荐测试条件。

修改环境变量后重建容器配置，但不重建前端：

```bash
docker compose up -d --force-recreate
```

检查运行状态、日志及资源：

```bash
docker compose ps
docker compose logs --tail=100
docker stats --no-stream
```

不要直接运行含未审核覆盖配置的操作。回退时保留上一版 `.output`/镜像及配置，按版本切换；当前无数据库迁移。

## 3. 容量和验收

Nuxt 容器初始上限512MiB，Node堆256MiB，CPU限制1核；Nginx使用已有实例。此配置是候选限额，不是2GB稳定性保证。

需要在服务器完成24小时运行、OOM/内存/CPU/日志/并发验证，并确认不影响现有业务。现有服务器地域不默认新加坡；OSS移至二期。

越南验收继续遵循 [一期D步](../一期D步/一期D步_上线与越南验收方案.md)，未验证不能声明越南已达标。

## 4. 本地验证记录

- Node 24.22.0，Nuxt 4.6.2，Vue 3.5.44。
- 数据查询、路由匹配、词条完整性：3项测试通过。
- 生产构建、类型检查通过。
- HTTP测试：中英文页面、产品详情、404、全部提供素材访问通过。
- 默认语言 `zh/en` 分别启动验证通过；Cookie记忆优先通过。
- 无界面Chromium：搜索、分页、详情、语言切换/记忆、手机导航、轮播控制及联系兜底验证。
- 375/768/1440宽度代表页面无整页横向溢出。
- 浏览器视觉人工验收、服务器部署/负载/24小时运行和越南测试尚未完成。

构建存在 Vue 依赖的导出映射弃用提示，未阻止构建。官方 npm 安全审计有上游 `braces`、`node-forge` 及相关间接依赖告警，已升级 Nuxt并修复可修复依赖，未使用强制降级。开发服务不得暴露公网，正式发布前复查上游补丁及生产产物依赖。
