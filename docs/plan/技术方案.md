## 1. 推荐技术栈

| 层级 | 选型 | 用途及理由 |
| --- | --- | --- |
| 官网 | Vue 3 + Nuxt 4 + TypeScript | 保留 Vue 技术路线，SSR 支持中英文内容收录和首屏展示 |
| 官网样式 | SCSS + CSS 变量 + 自定义组件 | 建立工业企业视觉，不把官网做成管理系统风格 |
| 官网交互 | Nuxt i18n、按需使用 Swiper | 双语路由、轮播；避免冗余组件依赖 |
| 管理后台 | 同一Nuxt工程的/admin + Vue 3 + TypeScript + Element Plus | 表格、表单、上传、弹窗；不新增独立Vite工程 |
| 后台状态/请求 | Vue Router、Pinia、Axios | 管理路由、登录状态、接口请求；官网优先 Nuxt useFetch |
| 服务端 | JDK 17 + Spring Boot 3.5.x | 遵循现有 Java 规范；实施时确认该版本线安全维护情况 |
| 数据访问 | MyBatis + MySQL 8.4 LTS | SQL 可控，适合分类、产品、文章和线索查询 |
| 缓存/会话 | 一期本机缓存、Servlet Session；二期Redis | 单实例起步，二期评估共享缓存、会话及原子限流 |
| 权限 | Spring Security + BCrypt | 服务端认证授权；不使用 MD5 保存密码 |
| 文档 | Knife4j + SpringDoc-OpenAPI | Knife4j 提供调试界面，SpringDoc 生成标准定义；保留 Markdown/JSON 交付 |
| 构建 | Maven 父 POM + 前端锁文件 | 统一依赖版本并保证构建可复现 |
| 文件 | 一期服务器独立磁盘目录；二期OSS适配及按需CDN | 私有与公开隔离，不接转码点播；地域按越南实测评估 |
| 客服 | 单一第三方人工客服入口，平台待确认 | 按需加载，不自建通信平台；无 AI 依赖或前端入口 |
| 反向代理 | Nginx + HTTPS | 统一域名入口、静态资源、API 代理 |
| 部署 | Linux + Docker Compose | 官网 SSR、Java、数据库、缓存分容器管理 |
| 测试 | JUnit 5、Spring Boot Test、Vitest、Playwright | 业务、接口、组件及关键端到端流程 |

版本规则：

- 表格确定技术路线，具体补丁版本在批准后查阅官方发布信息并做兼容性验证，再锁定。
- 前端采用 Node.js 24 LTS 作为候选运行时，验证 Nuxt/Vite/插件要求后确定。
- Java 组件优先由 Spring Boot BOM 管理，其他依赖集中在父 POM。
- 不使用 SNAPSHOT，不随意采用未验证的“最新版本”。
- 若 Spring Boot 3.5 维护状态不满足生产要求，先说明替代版本的兼容性和升级代价，再确认调整。

## 2. 为什么官网不直接用普通 Vue 单页应用

普通 Vue/Vite SPA 的主要正文依赖浏览器执行 JavaScript，不利于部分爬虫及初始内容展示。

Nuxt 是 Vue 框架，不是另换一套前端技术。它在服务端生成产品和文章 HTML，浏览器继续通过 Vue 交互。

代价是生产环境需要维护一个 Node.js SSR 服务，不能仅上传静态文件到 Nginx。

一期采用 SSR 加缓存，不选全站构建时静态生成，以免后台发布每次都需要全站重新构建。

Element Plus 主要用于后台；官网以定制展示组件为主，必要时按需使用，避免默认后台样式与体积影响。

## 3. 部署与请求路径

```text
浏览器 / 搜索引擎
        |
    Nginx HTTPS
        |
        +-- /zh/**、/en/** --> Nuxt SSR --> Java 公共 API
        +-- /admin/** ------> 同一Nuxt工程的管理后台
        +-- /api/** --------> Spring Boot
        +-- /media/** ------> Nginx alias公开磁盘目录（二期可适配OSS）
                                  |
                                  +-- MySQL
                                  +-- 本机会话/缓存（二期Redis）
                                  +-- 文件存储
```

- Node 不承载第二套业务规则，不直接读写数据库。
- Java 负责发布状态、语言可见性、参数校验、权限和询盘事务。
- 公共 API 与管理 API 分离；后台登录 Cookie 不转发给官网公共 SSR 请求。
- 数据库、Redis、Java 内部端口不直接暴露公网。
- 媒体区分公开与私有；草稿附件、线索导出不得放到无鉴权的静态公开目录。
- 当前复用2核2GB单机测试，Nuxt、Java、MySQL需设置资源限制；一期不运行Redis。构建和资料处理不在该机进行。
- 一期不运行 Dify、向量数据库、Embedding 或模型服务；未来 AI 资源另行评估。

## 4. 工程结构

```text
项目根目录/
  website/                 Nuxt 双语官网
  website/app/pages/admin.vue  同一Nuxt工程的后台入口
  backend/
    pom.xml                父 POM 和统一依赖管理
    common/                Result、异常、基础工具
    application/           启动模块和业务功能包
  deploy/                  部署配置
  docs/
    api/md、api/json        公开及共用接口
    admin/md、admin/json    管理及认证接口
    admin/                 后台前端与Java说明
    plan/                  需求、技术、Git、一期及二期方案
    JAVA_API_INDEX.md      接口总索引
```

后端包结构按 `com.<企业标识>.<项目名>.<模块名>`，模块内设 `controller`、`service/impl`、`mapper`、`entity`、`dto`、`vo`、`config` 等。

候选模块：`auth`、`catalog`、`content`、`inquiry`、`media`、`site`、`audit`。

语言扩展由 `site` 管理；人工客服由独立 UI 组件和受控站点配置接入，不允许后台注入任意脚本。第三方域名须加入明确的 CSP 白名单。

AI 仅预留架构边界：未来新增服务端适配模块，复用产品/文章数据，不让前端直接调用模型密钥。一期不创建空壳 AI 接口、数据库、管理页面或隐藏加载的聊天 SDK，不在 HTML/前端包中加入 AI 入口和占位。

企业标识及项目名在实施前确定；不先写死虚构公司包名。

## 5. 数据模型概要

| 对象 | 存储设计 |
| --- | --- |
| 语言 | 语言代码、显示名称、排序、默认语言及启用状态；翻译内容独立关联 |
| 材料分类 | 一期从产品category字段只读汇总，不设置独立新增维护入口 |
| 品牌 | 一期从产品brand字段只读汇总；合作商标图片由固定媒体位置管理 |
| 产品 | 产品主表、分类/品牌引用；产品语言内容表 |
| 产品参数 | 产品参数行及语言标签，保留单位、条件、标准 |
| 应用标签 | 标签及翻译、产品关联表 |
| 产品媒体 | 产品管理中选择/上传图片并关联媒体ID；不出现在网站媒体资源列表 |
| 新闻/百科 | 文章主表、文章类型及语言内容表 |
| 企业介绍/首页 | 轮播图与合作商标分组，仅修改/替换固定位置，不增删；其他模块按需求确认 |
| 荣誉资质 | 证书及语言内容，关联媒体 |
| 询盘 | 联系方式、产品来源、语言、状态及负责人 |
| 跟进记录 | 询盘操作和跟进备注 |
| 权限/日志 | 用户、角色、权限及关联表，操作审计 |
| 通知任务 | 待发送邮件记录、重试次数及发送状态 |

- 语言内容唯一约束：业务对象 ID + 语言代码。
- 公开 URL 使用稳定标识，不因修改标题自动变化；分类和品牌标识保证唯一。
- 不将中文/英文所有内容塞入一个不可约束的大 JSON 字段。
- 状态、筛选字段及外键关联加必要索引；禁止无限制分页和全量查询。
- 删除分类、品牌和媒体前检查引用；产品下架与物理删除分开处理。
- 询盘数据保留与删除按隐私政策执行，不无限期默认保存。
- 参数值可展示为文本；如未来需要数值区间选型，再扩展类型、规范单位及索引。

## 6. 后端开发约束

- DTO 入参、VO 出参，禁止直接以实体作为接口模型。
- Validator 校验字段，复杂约束使用自定义校验；国际电话不套用纯国内手机号规则。
- 统一 `Result(code, msg, data)`，分页 data 含列表、总数、页码和页大小。
- 正确返回 HTTP 401、403、404、429 等状态，不把所有错误都包装成 HTTP 200。
- `@RestControllerAdvice` 处理异常，`@Slf4j` 输出脱敏上下文。
- 多表保存及询盘与通知任务保存使用明确传播行为和隔离级别的事务，异常回滚。
- 实体默认 Lombok，关键类/方法添加用途注释，复杂逻辑拆分。
- SpringDoc使用`@Operation`、`@Schema`等；接口公开/共用接口放`docs/api/md/`及`docs/api/json/`，管理/认证接口放`docs/admin/md/`及`docs/admin/json/`，`docs/JAVA_API_INDEX.md`保留总索引。
- Knife4j Jakarta starter 与 Spring Boot/SpringDoc 组合验证后锁定，注意 starter 已有传递依赖，避免重复引入冲突；生产关闭或仅授权内网访问。
- 配置为 `application.yml` 和 `application-dev/test/prod.yml`。
- 数据库账号、密码、SMTP、密钥通过环境变量注入；不采用明文示例密码作为实际配置。
- 生产 OpenAPI 页面限制访问，不公开后台接口调试入口。

## 7. 认证及内容安全

后台选服务端会话，不默认引入复杂 JWT 刷新机制：

- 同域后台使用HttpOnly、Secure、SameSite Cookie，一期Servlet Session；二期再评估Redis共享会话。
- 启用 CSRF 保护，状态变更必须携带有效 CSRF 凭证。
- 登录限流、会话超时、退出失效、禁用用户后撤销会话。
- 页面按钮隐藏仅改善体验，真正权限检查在 Java 接口执行。
- 联系方式明文读取及导出需要独立权限并记录日志。
- 富文本服务端清洗，限制 HTML 标签及 URL 协议，防止存储型 XSS。
- 上传检查文件类型、文件头、大小、文件名及路径；一期不接受可执行文件和原始 SVG。
- 图片/PDF/视频设置各自大小限制，具体阈值按企业资料确定。
- 不在日志、前端包、SSR 输出或错误响应中暴露密钥和内部路径。

## 8. 双语 SEO 与缓存

- 顶部中英文切换保持内容身份，语言路由通用化，后续扩展 `/vi/` 等路径。
- 默认 `SITE_DEFAULT_LOCALE=zh`，Nuxt 服务端运行时配置读取该变量并通过公共配置输出有效默认语言；Java 在 yml 中以 `${SITE_DEFAULT_LOCALE:zh}` 引用。Compose 为相关服务注入同一值。
- 环境默认语言启动校验，修改后重启相关服务，无需重建前端；URL 明确语言优先于已保存选择和环境默认值。根路径按选择跳转时不使用跨访客共享缓存。
- 候选 API：`GET /api/public/languages` 查询已启用语言，`/api/admin/languages` 管理语言配置，`/api/admin/translations` 维护界面翻译；此处只定义接口边界，不代表已实现。
- 内容 API 使用显式 locale，拒绝未启用语言；增加语言前校验界面词条及最低发布内容。界面词条采用受控 key，不执行来自后台的脚本或模板。
- 每个已发布语言版本输出独立 title、description、正文、canonical。
- `hreflang` 仅关联实际发布的对应语言版本，不生成不存在的英文链接。
- 使用 Organization、BreadcrumbList、Article、Product 等适合的结构化数据；不虚构价格、库存、评分。
- 搜索结果页、后台、草稿不收录；分页 URL 及筛选 URL 明确规范，避免重复页面泛滥。
- 产品下架返回合适的 404/410 或有依据的重定向，不一律返回首页和 200。
- 二期Redis key可采用`catalog:category:zh`、`product:detail:en:<id>`；一期缓存仅在本机，重启失效。
- 数据缓存、Nuxt HTML 缓存均包含语言和发布维度。
- 数据事务提交后触发公共缓存及 SSR 缓存失效；失败可重试，并配置有限 TTL 兜底。
- 询盘、认证和后台请求不使用共享页面缓存。
- 数据库备份与媒体备份一起规划，公开文件链接随存储适配保持稳定。

## 9. 实施顺序和验收关卡

1. 批准需求和技术方案，确定企业标识、素材及产品数据样例。
2. 绘制页面原型和视觉规范，确认首页、产品列表、产品详情和后台产品编辑页。
3. 搭建工程、数据库迁移、统一异常、安全和媒体基础。
4. 实现双语产品及文章维护、产品图片、分类/品牌只读汇总和轮播/商标固定位置替换，验证发布流程。
5. 实现双语官网页面、SEO 和缓存联动。
6. 实现询盘、回电申请、权限和跟进闭环。
7. 完成测试、接口文档、部署说明和备份恢复验证。

关键测试：

- 产品与语言内容事务回滚、分类/品牌引用校验。
- 未发布英文内容不会进入英文详情、列表或 sitemap。
- 发布后可见、下架后隐藏，Java 数据缓存与 Nuxt 页面缓存一致。
- 搜索筛选与分页、型号特殊字符、无结果及不存在路径。
- 询盘验证码失败、限流、重复提交、保存失败及邮件失败。
- 401/403、CSRF、上传拒绝、富文本 XSS、敏感字段权限。
- 中英文切换、移动端筛选、参数表、SSR HTML 与结构化数据。
- 人工客服中英文提示、在线/离线状态、第三方加载失败时询盘兜底；访客页面不存在 AI 入口或请求。
