# 官网管理后台

## 访问与范围

运行官网后访问 `/admin`，例如 `http://localhost:3000/admin`。采用 Element Plus，独立左侧菜单和工作台，不显示官网导航/页脚。

- 工作台：数据库产品、文章、询盘数量及接入进度；媒体数量仍为固定预览位置。
- 产品管理：名称/分类/品牌搜索、分类和状态筛选、分页、新增、编辑、确认删除；产品表单选择/替换JPG、PNG、WebP图片，并显示预览。
- 分类与品牌：从产品管理记录汇总现有类型与产品数量，只读展示，不提供独立新增、编辑或删除。
- 文章管理：单一“标题”必填，不再区分中英文标题；分类、内容和英文内容选填，支持分类筛选。两种语言页面共用标题。
- 媒体资源：轮播图与合作商标分开展示，当前固定3张轮播和1张商标合集，仅修改/替换图片，不提供增删，不收录产品图片；20MB/文件。
- 客户询盘：仅已登录管理员可查看完整电话及邮箱；支持全部/中文/English分区，按提交时间从新到旧排序，单条详情展示完整留言和联系信息，支持更新处理状态。
- 日期与Excel：选择开始/结束日期（包含两日全天，按数据库服务器时间），一键导出该日期及语言范围的全部询盘为真正的`.xlsx`。不选日期导出全部时间，不限制100条；联系方式和留言写为文本，防止Excel公式执行。历史产品/网站字段仍保留。
- 日期查询直接请求Java接口，由SQL对`inquiry_record.created_at`筛选，不再依赖浏览器截取时间字段。结束日期默认当前本地日历日期；选择日期/语言自动重新查询，也可点击“查询”。点击“清除日期”可查看全部时间。结束日使用次日零点排他边界，包含结束日全天。
- 网站设置：中文和English信息分区（企业名称、介绍、地址），共用联系邮箱、电话、默认语言和HTTPS客服地址；保存到MySQL后官网刷新生效。

产品和文章通过同源 `/api/**` 代理读取及保存Java/MySQL，刷新后保留。官网只读取已发布产品/文章，数据库为空时不填充静态示例；Java不可用时返回明确错误。分类与品牌由数据库产品记录汇总。

文章API使用 `title`，不返回文章的 `name/nameEn`。共用内容表中 `name` 保存文章标题，历史 `name_en` 保留但不参与文章标题编辑或显示，无需重新导入SQL。`description` 对应表单“内容”。

产品图片在保存时上传私有目录、发布公开副本，再关联imageId；公开图片通过 `/api/public/media/{id}/image` 读取。当前即使产品为草稿，上传图片也会发布；产品保存失败可能留存媒体，不要上传敏感图片。仅轮播、商标替换仍为当前页面预览。

联系页随URL语言显示中文或英文表单，姓名、邮箱、电话、留言必填；其余选填。
已移除网站地址及产品选择选项。提交携带CSRF，服务端限流并写入MySQL。
网站设置API为`GET /api/public/site-settings`、`GET/PUT /api/admin/site-settings`；
未保存时沿用启动环境值，已保存时以数据库为准，不需要重建前端。

后台使用Java管理员登录、Session和CSRF；写请求获取最新CSRF令牌，服务端验证权限。开发密码来自后端 `.env`，生产必须使用BCrypt。尚未完成生产部署和容量验收。

## 服务器文件存储预留

尚未核实实际宝塔部署目录，所以不自动指定或创建磁盘目录。

配置模板：[媒体存储模板](../../website/deploy/media-storage.env.example)，Java实际配置见[后端环境模板](../../backend/.env.example)：

| 变量 | 说明 |
| --- | --- |
| `MEDIA_STORAGE_TYPE` | 起步采用 local，未来可适配 OSS |
| `MEDIA_PUBLIC_ROOT` | 已发布媒体绝对目录，待核实后填写 |
| `MEDIA_PRIVATE_ROOT` | 草稿/内部资料目录，与公开目录隔离 |
| `MEDIA_PUBLIC_URL_PREFIX` | 建议 `/media/`，可配置 |
| `MEDIA_MAX_UPLOAD_BYTES` | 未来服务端强制限制，不以浏览器校验代替 |

这些目录由Java后端读取，产品图片上传已接入。磁盘目录不放进 Nuxt public runtimeConfig，也不向客户端返回。

未来数据库保存 object key、类型、大小、版本及权限，产品公共接口返回访问 URL。独立上传目录必须在 `.output` 外，并有磁盘配额、异机备份；Docker Java 容器应显式挂载持久化目录。

Nginx映射模板：[公开媒体映射](../../website/deploy/media-location.conf.example)。其中`__VERIFIED_PUBLIC_MEDIA_ROOT__`必须替换成实际目录，经备份与审核后合并进对应宝塔站点；不要直接启用模板。

公开目录仅放已审核资源；草稿发布时由服务端移动/复制，不直接放入公开位置。上传时鉴权、随机文件名、文件头检测、防路径穿越；禁止脚本执行、目录列表和公开私有文件。PDF等可能含主动内容，后续应结合独立媒体域名/下载策略评估。

## 本地联调

先按[后端说明](../../backend/README.md)运行MySQL及Java，再启动Nuxt。Java默认地址 `http://127.0.0.1:8080`，可通过 `NUXT_JAVA_API_BASE` 调整。不要重复导入初始化SQL；当前手动建表的本地库暂时禁用Flyway。

真实联调用例位于 `website/tests/e2e/mysql.spec.ts`，使用无界面浏览器新增临时产品、检查SQL落库、刷新与双语SSR，并清理测试记录。仅在独立本地开发库运行；需通过环境变量提供管理员密码、数据库及测试媒体目录。

后续仍需接入固定轮播/商标替换。生产联系表单还需评估验证码、隐私政策和受信代理限流；当前未连接云服务器，也未部署 AI。
